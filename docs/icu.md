# Данные ICU: почему без них `Intl` — не браузерный

Собранный V8, на котором стоит движок, содержит ICU целиком, но **без данных**:
без файла `icudtl.dat` любой вызов `Intl` роняет процесс. Поэтому слой маскировки
подменял `Intl` и локальные форматы дат своей заглушкой.

Заглушка отвечает не то, что браузер, и заметно:

| вопрос | заглушка | Chrome |
|---|---|---|
| `new Intl.NumberFormat('de-DE',{style:'currency',currency:'EUR'}).format(1234.5)` | `1234.5` | `1.234,50 €` |
| `new Intl.PluralRules('ru').select(2)` | `other` | `few` |
| `new Intl.RelativeTimeFormat('en').format(-1,'day')` | `-1 day` | `1 day ago` |
| `(1234.5678).toLocaleString()` | `1234.5678` | `1,234.568` |
| `'a'.localeCompare('B')` | `1` | `-1` |
| `[...new Intl.Segmenter('en',{granularity:'word'}).segment('a b')].length` | `1` | `3` |
| `Intl.DateTimeFormat().resolvedOptions()` | четыре поля | все |

Из двадцати двух проверок, какие обычно делает сборщик отпечатков, двадцать
расходились с Chrome — и четырнадцать из них закрывались одним файлом.

## Как дать данные

Положить `icudtl.dat` рядом с двоичным файлом или указать путь:

```
NOKK_ICU_DATA=/путь/к/icudtl.dat nokk --load https://example.com
```

Движок сообщит `ICU data loaded` и отойдёт в сторону: `Intl` дальше отвечает сам.
Без файла остаётся заглушка — работает, но врёт на локалях.

## Какой именно файл

**ICU 74.** Привязка зовёт `udata_setCommonData_74`, и данные другой версии
принимаются, но потом каждый вызов отвечает `TypeError: Internal error. Icu
error.` Проверено на этой машине: файлы из сборок Electron того времени
(≈10 467 680 байт) подходят, из Chromium 128+ и новее — нет.

Взять можно из релиза [icu4c](https://github.com/unicode-org/icu/releases)
(пакет `icu4c-74_2-data-bin-*`) — данные ICU лежат под лицензией Unicode и
распространяются свободно. Файл занимает около десяти мегабайт; при желании его
можно пересобрать под нужные локали инструментом `pkgdata` из того же релиза.
